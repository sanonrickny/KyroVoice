The signal chain

Five stages between your voice and your cursor.

Holding the hotkey starts the chain. Releasing it runs the rest. Every stage is local, and the whole thing is one Swift pipeline you can read in an afternoon.

01

Hold the key

A Carbon hotkey catches both the press and the release, so push to talk feels like a walkie talkie. Tap to toggle is a setting.

HotkeyManager

An AVAudioEngine tap pulls microphone audio and resamples it to 16 kHz Float32, the format the model expects.

Models

Two weights, both offline after the first download.

KyroVoice runs NVIDIA Parakeet TDT 0.6B through FluidAudio's CoreML build. The model downloads once into Application Support and stays there. English is the default because it is the more accurate of the two.

Modes

It reads the room before it writes.

KyroVoice checks which app is in front and picks a mode from its bundle ID. VS Code, Xcode and iTerm get Code. Mail and Outlook get Email. Everything else gets your default. You can override it from the menu bar at any time.

Normal

Notes, Slack, browsers, anywhere else

Normalizes whitespace and unicode, drops true disfluencies, fixes punctuation spacing, and capitalizes sentences. Words that only look like filler are left alone.

Self check

It talks to itself to prove it still listens.

There is no test target. There are two flags. The first asserts every text rule offline in a few milliseconds. The second is the interesting one: it uses the macOS speech synthesizer to say a sentence out loud, feeds that audio to the real model, and asserts the text that comes out the other end. Text to speech to text, end to end, on one machine.

# every TextProcessor rule, offline, instant
$ ./.build/release/KyroVoice --self-check
TextProcessor self-check: all checks passed

# `say` speaks it, Parakeet transcribes it, the pipeline is asserted
$ ./.build/release/KyroVoice --speech-check
say -v Alex  ->  audio  ->  SpeechEngine  ->  TextProcessor  ->  ok
Privacy

The only thing that ever leaves is the model download.

Dictation apps usually ship your voice to a server. This one does the recognition on the same chip that runs Face ID. After the model is on disk you can dictate with the Wi-Fi off.

  • AudioHeld in memory for the length of one hotkey press, then dropped. Nothing is written to disk and nothing is uploaded.
  • RecognitionCoreML on the Apple Neural Engine, in process. No API key, no account, no telemetry.
  • HistoryRecent transcripts stay on your Mac so you can copy something again. Clear it from the menu bar.
  • MicrophoneRequired to record while the hotkey is held.
  • AccessibilityRequired to place text at the cursor through the accessibility API.
  • Input monitoringRequired to post the synthetic ⌘V that pastes into the app in front.
Install

Two commands, then hold the key.

You need macOS 14 or newer on Apple silicon, and Xcode 15 or newer. The setup script creates a persistent signing identity so macOS keeps your permission grants across rebuilds instead of asking again every time.

$ git clone https://github.com/sanonrickny/KyroVoice.git
$ cd KyroVoice

# once: signing identity, so TCC grants survive rebuilds
$ ./setup_deps.sh

# build, install to /Applications, relaunch
$ make install
  • Hotkey⌘ ⇧ Space held to talk. Release to inject.
  • make runBuilds and launches from .build/ without installing.
  • First dictationDownloads the English model once, about 450 MB. Everything after that is offline.
